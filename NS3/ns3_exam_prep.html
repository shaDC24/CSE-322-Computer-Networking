Chapter 5 — Conceptual Overview
first.cc · NodeContainer · Topology Helpers · Simulator
  • NS-3 is a discrete-event network simulator written in C++, using the ns3 namespace.
  • Module Includes: #include "ns3/core-module.h", network-module.h, internet-module.h, point-to-point-module.h, applications-module.h
  • NodeContainer — creates and manages simulation nodes. nodes.Create(2) creates 2 nodes.
  • PointToPointHelper — sets up P2P link. Attributes: DataRate (device) and Delay (channel). Then pointToPoint.Install(nodes) returns a NetDeviceContainer.
  • InternetStackHelper — installs TCP/IP stack on nodes with stack.Install(nodes).
  • Ipv4AddressHelper — assigns IP addresses. address.SetBase("10.1.1.0","255.255.255.0") then address.Assign(devices).
  • UdpEchoServerHelper — installs server on a node with port number. Start(Seconds(1.0)) and Stop(Seconds(10.0)).
  • UdpEchoClientHelper — takes server IP + port. Attributes: MaxPackets, Interval, PacketSize.
  • Simulator::Run() → runs all events. Simulator::Destroy() → cleans up. Simulator::Stop(t) → forces stop at time t.
  • Simulation stops when: (a) event queue is empty, or (b) a Stop event is reached. Self-sustaining events (like beacons) require an explicit Simulator::Stop().
  • Scripts go in scratch/ directory and built with ./ns3 build, run with ./ns3 run scratch/myfirst.
⚙️
Chapter 6 — Tweaking
Logging · Command Line Args · ASCII Tracing · PCAP Tracing
  • 7 Log Levels (increasing verbosity): LOG_ERROR, LOG_WARN, LOG_DEBUG, LOG_INFO, LOG_FUNCTION, LOG_LOGIC, LOG_ALL. Also NS_LOG_UNCOND (always prints).
  • LOG_LEVEL_INFO enables INFO + all levels below it (DEBUG, WARN, ERROR).
  • Enable logging in code: LogComponentEnable("UdpEchoClientApplication", LOG_LEVEL_INFO)
  • Enable via shell: export NS_LOG=UdpEchoClientApplication=level_all
  • Logging is only available in debug builds — not in optimized builds.
  • Command Line Arguments: Use CommandLine cmd; cmd.AddValue("nPackets", "...", nPackets); cmd.Parse(argc, argv); then run with ./ns3 run "scratch/myfirst --nPackets=5"
  • ASCII Tracing: AsciiTraceHelper ascii; p2p.EnableAsciiAll(ascii.CreateFileStream("myfirst.tr"))
  • PCAP Tracing (all): pointToPoint.EnablePcapAll("myfirst") — creates myfirst-N-M.pcap files (N=node, M=device).
  • PCAP Tracing (specific): csma.EnablePcap("second", csmaDevices.Get(1), true) — last arg = promiscuous mode.
  • Use tcpdump -nn -tt -r filename.pcap to read pcap files.
🌐
Chapter 7 — Building Topologies
second.cc (P2P+CSMA) · third.cc (P2P+CSMA+WiFi) · Queues
  • second.cc topology: P2P link (10.1.1.0) connected to a CSMA bus network (10.1.2.0). Client on P2P node, server on last CSMA node.
  • CsmaHelper: csma.SetChannelAttribute("DataRate", StringValue("100Mbps")) and Delay set in NanoSeconds. Data rate is a channel attribute (not device) in CSMA.
  • Global Routing: Ipv4GlobalRoutingHelper::PopulateRoutingTables() — acts like OSPF, auto-configures all routing tables.
  • Promiscuous PCAP: csma.EnablePcap("second", csmaDevices.Get(1), true) — sniffs all traffic like tcpdump. Non-promiscuous sees only that node's traffic.
  • PCAP file naming: <prefix>-<node>-<device>.pcap
  • ARP is visible in CSMA traces — node must resolve MAC before sending.
  • third.cc topology: Adds Wi-Fi network (10.1.3.0) with STAs + AP on top of second.cc topology.
  • Wifi Setup: YansWifiChannelHelper → YansWifiPhyHelper → WifiMacHelper → WifiHelper. STA uses ns3::StaWifiMac, AP uses ns3::ApWifiMac.
  • Mobility: GridPositionAllocator for initial placement. STAs use RandomWalk2dMobilityModel; AP uses ConstantPositionMobilityModel.
  • WiFi beacons are self-sustaining → must call Simulator::Stop(Seconds(10.0)).
  • Two queue layers: (1) Traffic Control Layer (TDL) — device-independent QoS; (2) NetDevice layer — device-specific. Default is PFifoFastQueueDisc (1000 packets).
  • Default NetDevice queue: DropTail, 100 packets for P2P, CSMA, WiFi.
🔍
Chapter 8 — Tracing
Trace Sources · Trace Sinks · Callbacks · Config Paths
  • Trace Source: An entity that signals when events happen — e.g., packet received, TCP congestion window change.
  • Trace Sink: A function that consumes trace events. It must have a matching callback signature.
  • TracedValue<T>: Wraps a variable so any change triggers a callback with old + new value.
  • TracedCallback<T1,...>: A list of callbacks, all called when an event fires.
  • Connect without context: obj->TraceConnectWithoutContext("AttrName", MakeCallback(&MyFunc))
  • Connect with context (config path): Config::Connect("/NodeList/7/$ns3::MobilityModel/CourseChange", MakeCallback(&CourseChange))
  • Config Path syntax: /NodeList/[i]/$ns3::TypeName/TraceSourceName. The $ means GetObject (aggregated object).
  • Callback signature for CourseChange (with context): void fn(std::string context, Ptr<const MobilityModel> model)
  • NS_LOG is not tracing — tracing is stable, API-driven, available in optimized builds. NS_LOG is debug-only.
  • Find all trace sources in ns-3 Doxygen: "All TraceSources" list. Config paths are in the class "Detailed Description".
📊
Chapter 9 — Data Collection
GnuplotHelper · FileHelper · Probes · Trace Types
  • Data Collection framework introduced in ns-3.18 — provides structured output from simulations.
  • GnuplotHelper: Auto-generates gnuplot .plt, .dat, and a shell script to produce a .png plot.
  • plotHelper.ConfigurePlot("prefix","Title","X-Axis","Y-Axis") sets up the plot.
  • plotHelper.PlotProbe(probeType, tracePath, "OutputBytes", "Label", GnuplotAggregator::KEY_BELOW) hooks trace source to plot.
  • FileHelper: Writes time-stamped data to text files. fileHelper.ConfigureFile("prefix", FileAggregator::FORMATTED).
  • fileHelper.Set2dFormat("Time = %.3e\tBytes = %.0f") sets format. fileHelper.WriteProbe(probeType, tracePath, "OutputBytes") hooks it.
  • Probe types: ns3::Ipv4PacketProbe, ns3::Ipv6PacketProbe, ns3::PacketProbe, ns3::ApplicationPacketProbe.
  • Wildcard * in trace path matches multiple nodes; GnuplotHelper overlays them on one plot; FileHelper creates separate files per match.

SHORT Q

Short Questions & Answers

SHORT What is ns-3 and what type of simulator is it? ▼
ANSWER

ns-3 is an open-source Discrete Event Simulator (DES) for network simulation. In a discrete-event simulator, each event is associated with a time, and the simulator processes events in chronological order. Events can schedule future events. The simulation stops when the event queue is empty or a Stop event is hit.

SHORT What is the purpose of the NodeContainer in ns-3? ▼
ANSWER

NodeContainer is a topology helper that creates, manages, and provides access to Node objects. A Node represents a computer in the simulation. Example:

NodeContainer nodes;
nodes.Create(2); // Creates 2 nodes
SHORT What is the difference between a NetDevice and a Channel in ns-3? ▼
ANSWER

A NetDevice corresponds to a network interface card (NIC) — hardware attached to a node. A Channel corresponds to the network cable or medium connecting devices. The PointToPointHelper configures both together: DataRate is a device attribute, Delay is a channel attribute.

SHORT What does InternetStackHelper do? ▼
ANSWER

It installs the Internet protocol stack (TCP, UDP, IP, etc.) on nodes. Without this, nodes cannot communicate using standard internet protocols.

InternetStackHelper stack;
stack.Install(nodes);
SHORT What are the 7 logging levels in ns-3? Which is most verbose? ▼
ANSWER

From least to most verbose: LOG_ERROR → LOG_WARN → LOG_DEBUG → LOG_INFO → LOG_FUNCTION → LOG_LOGIC → LOG_ALL.

LOG_ALL is the most verbose. Using LOG_LEVEL_X enables level X and all levels below it. NS_LOG_UNCOND always prints regardless of level settings.

SHORT When is Simulator::Stop() necessary? ▼
ANSWER

It is required when there are self-sustaining (recurring) events that keep rescheduling themselves and would prevent the event queue from ever becoming empty. Examples: Wi-Fi beacons (AP keeps sending them forever), FlowMonitor's periodic checks, RIPng routing table updates. Without Simulator::Stop(), the simulation runs forever.

SHORT What is the difference between a trace source and a trace sink? ▼
ANSWER

A trace source is a point in the simulation code that generates events/data (e.g., when a packet is received, when a TCP congestion window changes). A trace sink is a user-provided function (callback) that consumes these events and does something with the data (like logging or plotting). Trace sources are producers; trace sinks are consumers.

SHORT What does the $ symbol mean in a Config path like /NodeList/7/$ns3::MobilityModel/CourseChange? ▼
ANSWER

The $ prefix tells the Config system to call GetObject<TypeName>() to retrieve an aggregated object of that type from the current object. It's how ns-3 switches from one object type to another that was previously aggregated to it (e.g., switching from a Node to its MobilityModel).

SHORT What is the difference between promiscuous and non-promiscuous PCAP tracing? ▼
ANSWER

Promiscuous mode (true): The device sniffs all traffic on the network, including packets not addressed to it — like tcpdump. Non-promiscuous (false): Only captures packets sent or received by that specific device. In CSMA traces, a bystander node in non-promiscuous mode only sees ARP broadcasts, not unicast packets.

SHORT What is Ipv4GlobalRoutingHelper::PopulateRoutingTables() and why is it needed in second.cc? ▼
ANSWER

It automatically computes and installs routing tables on all nodes in the simulation. It works like OSPF but uses global knowledge (it can "see" the entire topology). In second.cc we have an internetwork (P2P + CSMA), so packets need routing between the two subnets — without this, packets cannot be forwarded across network boundaries.

SHORT What is a TracedValue<T>? ▼
ANSWER

A TracedValue<T> wraps a primitive data type and overloads the assignment operator so that whenever the value changes, it automatically invokes all registered callbacks with the old value and the new value. This is the core mechanism behind fine-grained ns-3 tracing.

SHORT What is the default queueing discipline installed on a NetDevice in ns-3? ▼
ANSWER

The default is PFifoFastQueueDisc (Priority FIFO Fast Queue Discipline), with a max size of 1000 packets, installed automatically when an IPv4/IPv6 address is assigned to an interface. At the device level, a DropTail queue of 100 packets is the default for P2P, CSMA, and WiFi devices.

SHORT What do GnuplotHelper and FileHelper do in Chapter 9? ▼
ANSWER

GnuplotHelper hooks a trace source to a data collection pipeline and automatically generates gnuplot files (.dat, .plt, .sh) that produce PNG plots of the data over time.

FileHelper is similar but writes timestamped data to formatted text files instead of plots. With a wildcard path, GnuplotHelper overlays all matches on one plot; FileHelper creates a separate file per match.

MCQ

Multiple Choice Questions

MCQ Which of the following is a device attribute (not a channel attribute) in PointToPointHelper? ▼
A) Delay
B) DataRate ✓
C) MTU
D) EncapsulationMode

Answer: B — DataRate is set on the PointToPointNetDevice (device attribute). Delay is set on the PointToPointChannel (channel attribute).

MCQ In ns-3, which method is called to clean up all created objects after a simulation? ▼
A) Simulator::Stop()
B) Simulator::Run()
C) Simulator::Destroy() ✓
D) Simulator::Reset()

Answer: C — Simulator::Destroy() cleans up all objects created during the simulation by calling all registered destruction hooks.

MCQ What does LOG_LEVEL_INFO enable? ▼
A) Only INFO messages
B) INFO, DEBUG, WARN, and ERROR messages ✓
C) All log messages including FUNCTION and LOGIC
D) INFO and FUNCTION only

Answer: B — LOG_LEVEL_X enables X and all levels below it (less verbose). INFO enables: INFO, DEBUG, WARN, ERROR.

MCQ Which class is used to set Wi-Fi station MAC type in third.cc? ▼
A) YansWifiChannelHelper
B) WifiMacHelper ✓
C) WifiHelper
D) YansWifiPhyHelper

Answer: B — WifiMacHelper is used to set the MAC type via mac.SetType("ns3::StaWifiMac", ...) for stations and "ns3::ApWifiMac" for access points.

MCQ In CSMA (second.cc), the DataRate attribute is set on which object? ▼
A) CsmaNetDevice (device)
B) CsmaChannel (channel) ✓
C) NodeContainer
D) InternetStackHelper

Answer: B — Unlike P2P where DataRate is a device attribute, in CSMA it is a channel attribute. This is because a shared CSMA medium must have one data rate for all attached devices (you can't mix 10Base-T and 100Base-T on the same bus).

MCQ NS_LOG output is available in which build type? ▼
A) Optimized builds only
B) Debug builds only ✓
C) Both debug and optimized builds
D) Release builds only

Answer: B — NS_LOG output is only available in debug builds. Tracing (not logging) is the mechanism to use in optimized builds for stable output.

MCQ What mobility model is used for Wi-Fi STA nodes in third.cc? ▼
A) ConstantPositionMobilityModel
B) GridPositionAllocator
C) RandomWalk2dMobilityModel ✓
D) ConstantVelocityMobilityModel

Answer: C — STAs use RandomWalk2dMobilityModel (move randomly within a bounding box). The AP uses ConstantPositionMobilityModel to stay fixed. GridPositionAllocator is used for initial placement only.

MCQ The PCAP filename second-2-0.pcap corresponds to which node and device? ▼
A) Node 0, Device 2
B) Node 0, Device 0 — second script
C) Node 2, Device 0 ✓
D) Second simulation, Node 2

Answer: C — PCAP files are named <prefix>-<node>-<device>.pcap. So second-2-0.pcap = prefix "second", node 2, device 0.

SCENARIO

Scenario-Based Questions (Output + Why)

SCENARIO What is the output when you run first.cc with default settings? Explain each line. ▼
OUTPUT + EXPLANATION
At time +2s client sent 1024 bytes to 10.1.1.2 port 9
At time +2.00369s server received 1024 bytes from 10.1.1.1 port 49153
At time +2.00369s server sent 1024 bytes to 10.1.1.1 port 49153
At time +2.00737s client received 1024 bytes from 10.1.1.2 port 9
  • Line 1: Client (10.1.1.1, node 0) starts at t=2s (not t=1s — server starts at 1s, client at 2s). It sends 1024 bytes to server at 10.1.1.2.
  • Line 2: Server receives it at t≈2.00369s. The delay is propagation (2ms) + transmission time over 5Mbps link. Server logs source address (client IP) and ephemeral port.
  • Line 3: Server immediately echoes the packet back at the same time.
  • Line 4: Client receives the echoed packet at t≈2.00737s (roughly 2× the one-way delay added to t=2s).

The simulation ends after t=10s when both Start/Stop events fire. The total round-trip is ~7.37ms.

SCENARIO You add Simulator::Stop(Seconds(1.0)) before Simulator::Run() in first.cc. What happens? Why? ▼
OUTPUT + EXPLANATION

Output: No output is printed at all.

Why: The Stop event fires at t=1.0s. The client starts at t=2.0s and the server starts at t=1.0s — but since the Stop event at t=1.0s terminates the simulation before t=2.0s, the echo client never gets to send its packet. No packets are sent, so no log messages are printed. The simulation exits immediately after the stop event.

SCENARIO In second.cc, when you run tcpdump -nn -tt -r second-2-0.pcap, you see ARP requests. Why? ▼
OUTPUT + EXPLANATION
2.007698 ARP, Request who-has 10.1.2.4 (ff:ff:ff:ff:ff:ff) tell 10.1.2.1, length 50
2.007710 ARP, Reply 10.1.2.4 is-at 00:00:00:00:00:06, length 50
2.007803 IP 10.1.1.1.49153 → 10.1.2.4.9: UDP, length 1024
...

Why ARP appears: The CSMA network uses Ethernet (MAC addresses). When node 1 wants to forward the packet to 10.1.2.4, it knows the IP but not the MAC address. It broadcasts an ARP Request to the entire CSMA bus (ff:ff:ff:ff:ff:ff = broadcast). Node 4 (which has 10.1.2.4) replies with its MAC. This is standard Ethernet ARP behavior — IP alone is not enough for layer-2 delivery on a bus network.

Node 2 is captured here because it is in promiscuous mode — it sees all traffic including ARP broadcasts and unicast packets it's not the target of.

SCENARIO You set export NS_LOG=UdpEchoClientApplication=level_all and run first.cc. How does the output change compared to the default? ▼
OUTPUT + EXPLANATION

Default output: Only 4 lines (sent/received messages at INFO level).

With level_all: Many additional lines appear showing every function call within the UdpEchoClientApplication, e.g.:

UdpEchoClientApplication:UdpEchoClient(0xef90d0)
UdpEchoClientApplication:SetDataSize(0xef90d0, 1024)
UdpEchoClientApplication:StartApplication(0xef90d0)
...

Why: level_all enables ALL log levels including LOG_FUNCTION which logs every method call. The NS_LOG environment variable overrides what was set by LogComponentEnable() in code, giving more verbosity at runtime without recompiling.

SCENARIO In third.cc, why must you call Simulator::Stop(Seconds(10.0)) explicitly? ▼
EXPLANATION

The Wi-Fi Access Point continuously generates beacon frames at regular intervals (e.g., every ~102ms). Each beacon schedules the next beacon — this creates a self-sustaining (recurring) event. The event queue never becomes empty on its own.

Without Simulator::Stop(), Simulator::Run() would never return — it would loop forever processing beacon events into infinite simulated time. The explicit stop forces the simulation to terminate at t=10s regardless of pending events.

Note: Simulator::Stop() must be called before Simulator::Run().

SCENARIO In fourth.cc (tracing example), after running myObject->m_myInt = 1234, what is printed and why? ▼
OUTPUT + EXPLANATION
Traced 0 to 1234

Why: m_myInt is a TracedValue<int32_t>, initialized to 0. When assigned 1234, the overloaded operator= fires the callback. The connected trace sink IntTrace receives the old value (0) and new value (1234) and prints them.

The connection was made via: myObject->TraceConnectWithoutContext("MyInteger", MakeCallback(&IntTrace))

SCENARIO You run second.cc with --nCsma=4. How does the server IP change? Where does the server now reside? ▼
OUTPUT + EXPLANATION
At time +2s client sent 1024 bytes to 10.1.2.5 port 9
...

Why: With nCsma=4 extra nodes, the CSMA subnet has 5 nodes (indices 0–4 in csmaNodes). The server is always installed on csmaNodes.Get(nCsma) = the 4th extra node (index 4). This gets assigned IP 10.1.2.5 (starting from 10.1.2.1 for node 0). With default nCsma=3, server is at 10.1.2.4; with nCsma=4, it's at 10.1.2.5.

CODE Complete the basic point-to-point topology (first.cc pattern). Fill the blanks for a 2-node echo simulation. ▼
COMPLETE CODE — first.cc
// 1. Include modules
#include "ns3/core-module.h"
#include "ns3/network-module.h"
#include "ns3/internet-module.h"
#include "ns3/point-to-point-module.h"
#include "ns3/applications-module.h"

using namespace ns3;

int main(int argc, char* argv[]) {
  // 2. Create nodes
  NodeContainer nodes;
  nodes.Create(2);

  // 3. Set up P2P link
  PointToPointHelper pointToPoint;
  pointToPoint.SetDeviceAttribute("DataRate", StringValue("5Mbps"));
  pointToPoint.SetChannelAttribute("Delay", StringValue("2ms"));

  // 4. Install devices
  NetDeviceContainer devices;
  devices = pointToPoint.Install(nodes);

  // 5. Install Internet stack
  InternetStackHelper stack;
  stack.Install(nodes);

  // 6. Assign IP addresses
  Ipv4AddressHelper address;
  address.SetBase("10.1.1.0", "255.255.255.0");
  Ipv4InterfaceContainer interfaces = address.Assign(devices);

  // 7. Install server on node 1
  UdpEchoServerHelper echoServer(9);
  ApplicationContainer serverApps = echoServer.Install(nodes.Get(1));
  serverApps.Start(Seconds(1.0));
  serverApps.Stop(Seconds(10.0));

  // 8. Install client on node 0 pointing to node 1
  UdpEchoClientHelper echoClient(interfaces.GetAddress(1), 9);
  echoClient.SetAttribute("MaxPackets", UintegerValue(1));
  echoClient.SetAttribute("Interval", TimeValue(Seconds(1.0)));
  echoClient.SetAttribute("PacketSize", UintegerValue(1024));
  ApplicationContainer clientApps = echoClient.Install(nodes.Get(0));
  clientApps.Start(Seconds(2.0));
  clientApps.Stop(Seconds(10.0));

  // 9. Run simulation
  Simulator::Run();
  Simulator::Destroy();
  return 0;
}
CODE How do you add a CSMA network to a P2P topology? Write the key code snippet for second.cc. ▼
KEY SNIPPET — second.cc CSMA setup
// Topology: P2P node0 --- node1 === csmaNode2, csmaNode3, csmaNode4 // 10.1.1.0 10.1.2.0
// Create P2P nodes
NodeContainer p2pNodes;
p2pNodes.Create(2);

// Create CSMA nodes: p2pNodes.Get(1) + 3 extra
NodeContainer csmaNodes;
csmaNodes.Add(p2pNodes.Get(1));   // node1 is shared
csmaNodes.Create(nCsma);           // nCsma extra nodes

// CSMA helper - DataRate is a CHANNEL attribute
CsmaHelper csma;
csma.SetChannelAttribute("DataRate", StringValue("100Mbps"));
csma.SetChannelAttribute("Delay", TimeValue(NanoSeconds(6560)));

NetDeviceContainer csmaDevices = csma.Install(csmaNodes);

// Install stacks (node1 already in csmaNodes, skip p2pNodes.Get(1))
InternetStackHelper stack;
stack.Install(p2pNodes.Get(0));
stack.Install(csmaNodes);

// Assign IPs
Ipv4AddressHelper address;
address.SetBase("10.1.1.0", "255.255.255.0");
Ipv4InterfaceContainer p2pInterfaces = address.Assign(p2pDevices);

address.SetBase("10.1.2.0", "255.255.255.0");
Ipv4InterfaceContainer csmaInterfaces = address.Assign(csmaDevices);

// Global routing (required for multi-network)
Ipv4GlobalRoutingHelper::PopulateRoutingTables();

// Enable promiscuous PCAP on CSMA node 1
csma.EnablePcap("second", csmaDevices.Get(1), true);
CODE Write the Wi-Fi setup code for third.cc — creating STA nodes and AP node with mobility. ▼
KEY SNIPPET — third.cc WiFi setup
// Create STA nodes; AP reuses leftmost P2P node
NodeContainer wifiStaNodes;
wifiStaNodes.Create(nWifi);
NodeContainer wifiApNode = p2pNodes.Get(0);

// PHY and Channel setup
YansWifiChannelHelper channel = YansWifiChannelHelper::Default();
YansWifiPhyHelper phy = YansWifiPhyHelper::Default();
phy.SetChannel(channel.Create());

// MAC setup
WifiMacHelper mac;
Ssid ssid = Ssid("ns-3-ssid");
WifiHelper wifi;

// Install STA devices
mac.SetType("ns3::StaWifiMac",
            "Ssid", SsidValue(ssid),
            "ActiveProbing", BooleanValue(false));
NetDeviceContainer staDevices = wifi.Install(phy, mac, wifiStaNodes);

// Install AP device
mac.SetType("ns3::ApWifiMac", "Ssid", SsidValue(ssid));
NetDeviceContainer apDevices = wifi.Install(phy, mac, wifiApNode);

// Mobility: STA nodes move randomly, AP stays fixed
MobilityHelper mobility;
mobility.SetPositionAllocator("ns3::GridPositionAllocator",
    "MinX", DoubleValue(0.0), "MinY", DoubleValue(0.0),
    "DeltaX", DoubleValue(5.0), "DeltaY", DoubleValue(10.0),
    "GridWidth", UintegerValue(3),
    "LayoutType", StringValue("RowFirst"));
mobility.SetMobilityModel("ns3::RandomWalk2dMobilityModel",
    "Bounds", RectangleValue(Rectangle(-50, 50, -50, 50)));
mobility.Install(wifiStaNodes);

mobility.SetMobilityModel("ns3::ConstantPositionMobilityModel");
mobility.Install(wifiApNode);

// Assign WiFi IPs (10.1.3.0)
address.SetBase("10.1.3.0", "255.255.255.0");
address.Assign(staDevices);
address.Assign(apDevices);

// WiFi beacons are recurring → MUST stop explicitly
Simulator::Stop(Seconds(10.0));
CODE Write a trace sink function and connect it to the CourseChange trace source using a Config path. ▼
TRACING CODE PATTERN
// Trace sink function — must match callback signature
void
CourseChange(std::string context, Ptr<const MobilityModel> model)
{
  Vector position = model->GetPosition();
  NS_LOG_UNCOND(context << " x = " << position.x
                        << ", y = " << position.y);
}

// In main(): build config path and connect
std::ostringstream oss;
oss << "/NodeList/"
    << wifiStaNodes.Get(nWifi - 1)->GetId()
    << "/$ns3::MobilityModel/CourseChange";

Config::Connect(oss.str(), MakeCallback(&CourseChange));
// Config::ConnectWithoutContext omits the context string parameter

The path structure: /NodeList/[nodeId]/$ns3::MobilityModel/CourseChange

  • NodeList — global list of all nodes
  • [nodeId] — index (from GetId())
  • $ns3::MobilityModel — GetObject call to retrieve aggregated mobility model
  • CourseChange — the trace source name

CODE How do you enable ASCII and PCAP tracing in ns-3? ▼

⚠️ Exam Reminders:

  • CSMA DataRate → channel attribute. P2P DataRate → device attribute.
  • Server starts at Seconds(1.0), client at Seconds(2.0) — client always starts AFTER server.
  • InternetStackHelper must be installed BEFORE assigning IP addresses.
  • In multi-network topologies, call PopulateRoutingTables() or packets won't route.
  • WiFi simulations need explicit Simulator::Stop() — beacons are self-sustaining events.
  • A shared node (like p2pNodes.Get(1) in csmaNodes) must NOT have stack installed twice.
  • Config path $TypeName = GetObject<TypeName>() call.
  • Trace sinks with Config::Connect get a context string; with ConnectWithoutContext they don't.
