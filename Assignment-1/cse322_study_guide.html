Socket Programming — মূল ধারণা

Network, IP, Port, Socket — সব কিছু এক জায়গায়

🌐 Network কী?

Network হলো একাধিক computer-এর সংযোগ। যখন দুটো বা তার বেশি computer একে অপরের সাথে communicate করতে পারে, তখন তাদের একটি network বলে। Internet হলো বিশ্বের সবচেয়ে বড় network।
Multiple computers connected together. Internet = global network via ISP routers and WLAN routers.

📍 IP Address কী?

IP Address হলো network-এ প্রতিটি machine-এর unique পরিচয়। ঠিক যেমন বাড়ির address দিয়ে বাড়ি খুঁজে পাওয়া যায়, IP address দিয়ে network-এ machine খুঁজে পাওয়া যায়। Format: 172.20.30.30

একটি machine যদি একাধিক network-এ connected থাকে, তাহলে প্রতিটি network-এর জন্য আলাদা IP হবে।
Unique identifier per network interface. Use ipconfig (Windows) or ifconfig (Linux) to check. One device can have multiple IPs (one per active interface).

🚪 Port কী?

Port হলো একটি logical channel। একটি computer-এ ২¹⁶ = 65536 টি port আছে। প্রতিটি program আলাদা port ব্যবহার করে communicate করে। কিছু port reserved (যেমন HTTP = 80, HTTPS = 443)।

Port দেখতে: netstat command ব্যবহার করো।
Logical endpoint (0–65535). Each program must acquire a port. Reserved ports: 80 (HTTP), 443 (HTTPS), 22 (SSH), 21 (FTP). Use netstat to see active ports.

🔗 Socket কী?

Socket হলো দুটো network application-এর মধ্যে একটি connection। প্রতিটি connection-এর জন্য একটি socket তৈরি হয়।

একটি socket জানে:
• Remote IP (কে connect করেছে)
• Remote Port (কোন port থেকে)
• Local Port (নিজের port)

Socket-এর দুটো buffer আছে: Input Buffer এবং Output Buffer।
Represents a single connection. Has input/output buffers. Multiple sockets can share the same port, but only one program can own a port.

⚖️ Socket vs Port

Port একটি program-এর হয়, কিন্তু socket একটি connection-এর হয়।

উদাহরণ: Server port 6666 ব্যবহার করছে। Client A এবং Client B দুজনেই connect করলে — server-এর দুটো আলাদা socket তৈরি হবে, কিন্তু দুটোই port 6666 ব্যবহার করছে।
Port is owned by a program. Socket is per connection. Server on port 6666 can have many sockets (one per client) all sharing the same port number.

📡 TCP কী?

TCP (Transmission Control Protocol) হলো সেই protocol যেটি socket connection establish করে। TCP reliable — মানে data যাবেই, হারাবে না। Socket programming মূলত TCP-র উপর কাজ করে।
Transmission Control Protocol — reliable, ordered, connection-oriented. Socket programming in Java (ServerSocket, Socket) uses TCP by default.

Java Socket API — কোড বোঝা

ServerSocket, Socket, ObjectInputStream, ObjectOutputStream — সব কিছু

📄 Basic/Server.java — Simple Server
package Basic;

import java.io.ObjectInputStream;
import java.io.ObjectOutputStream;
import java.net.ServerSocket;
import java.net.Socket;

public class Server {
    public static void main(String[] args) throws Exception {
        ServerSocket welcomeSocket = new ServerSocket(6666);  // Line A

        while(true) {                                              // Line B
            Socket socket = welcomeSocket.accept();               // Line C

            ObjectOutputStream out = new ObjectOutputStream(      // Line D
                socket.getOutputStream());
            ObjectInputStream in = new ObjectInputStream(        // Line E
                socket.getInputStream());

            out.writeObject("Hello from server");               // Line F
            String msg = (String) in.readObject();               // Line G
            System.out.println(msg);
        }
    }
}
Line A ServerSocket তৈরি করা হলো port 6666-এ। এটি server-এর "welcome door" — এখানে client-রা knock করবে।
Line B while(true) loop — server সবসময় চালু থাকবে। একজন client serve করার পরেও আরেকজনের জন্য wait করবে।
Line C accept() — blocking call। কোনো client connect না করা পর্যন্ত এখানেই থামবে। Client connect হলে একটি Socket object return করে।
Line D ObjectOutputStream — server থেকে client-এ data পাঠানোর channel (output buffer)। getOutputStream() socket-এর outgoing stream দেয়।
Line E ObjectInputStream — client থেকে server-এ data পড়ার channel (input buffer)। getInputStream() socket-এর incoming stream দেয়।
Line F writeObject() — client-এ String পাঠানো হলো। Object serialization ব্যবহার করে।
Line G readObject() — blocking call। Client কিছু না পাঠানো পর্যন্ত এখানে থামবে। Return type Object, তাই String-এ cast করতে হয়।
📄 Basic/Client.java — Simple Client
package Basic;

public class Client {
    public static void main(String[] args) throws Exception {
        Socket socket = new Socket("localhost", 6666);         // Line A
        System.out.println("Remote port: " + socket.getPort()); // Line B
        System.out.println("Local port: " + socket.getLocalPort());

        ObjectOutputStream out = new ObjectOutputStream(socket.getOutputStream());
        ObjectInputStream in = new ObjectInputStream(socket.getInputStream());

        String msg = (String) in.readObject();                  // Line C
        System.out.println(msg);

        out.writeObject("Hello from client");                  // Line D
    }
}
Line A new Socket("localhost", 6666) — server-এ connection করো। "localhost" মানে নিজের machine (127.0.0.1)। অন্য PC-র IP দিলে সেখানে connect হবে।
Line B getPort() — server-এর port (6666) return করে। getLocalPort() — client-এর নিজের random port return করে (যেমন 50320)।
Line C Server আগে message পাঠাচ্ছে, তাই client আগে readObject() করছে। Order গুরুত্বপূর্ণ — একদিক লিখলে অন্যদিক পড়তে হবে।
Line D এখন client server-এ message পাঠাচ্ছে। Server-এর readObject() এটিই পাবে।
📄 Threading/Server.java — Multi-Client Server
package Threading;

public class Server {
    public static void main(String[] args) throws Exception {
        ServerSocket welcomeSocket = new ServerSocket(6666);

        while(true) {
            Socket socket = welcomeSocket.accept();             // Line A

            Thread worker = new Worker(socket);               // Line B
            worker.start();                                     // Line C
        }
    }
}
Line A Main thread শুধু connection accept করে। কোনো client কাজ করে না — শুধু নতুন connection-এর জন্য wait করে।
Line B প্রতিটি client-এর জন্য নতুন Worker thread তৈরি। Worker হলো Thread-এর subclass যেখানে actual client handling হয়।
Line C worker.start() — নতুন thread শুরু। এই thread background-এ client handle করবে। Main thread আবার loop-এ ফিরে নতুন client-এর জন্য accept() করবে।
💡
Key PointThreading ছাড়া server একবারে শুধু একজন client serve করতে পারে। Thread ব্যবহার করলে multiple clients simultaneously serve করা যায়।
📄 Threading/Worker.java — Thread Handler
package Threading;

public class Worker extends Thread {       // Line A
    Socket socket;

    public Worker(Socket socket) {           // Line B
        this.socket = socket;
    }

    public void run() {                        // Line C
        try {
            ObjectOutputStream out = new ObjectOutputStream(
                this.socket.getOutputStream());
            ObjectInputStream in = new ObjectInputStream(
                this.socket.getInputStream());

            while (true) {                      // Line D
                Thread.sleep(1000);             // Line E
                Date date = new Date();
                out.writeObject(date.toString()); // Line F
            }
        } catch (IOException | InterruptedException e) {
            e.printStackTrace();
        }
    }
}
Line A Worker extends Thread — এটিকে Thread subclass করা হলো। run() method override করতে হবে।
Line B Constructor-এ socket receive করা হলো। এই socket দিয়েই specific client-এর সাথে communicate করবে।
Line C run() method — thread.start() call করলে এই method execute হয়। এখানে actual client logic থাকে।
Line D-F প্রতি 1 second পর current time পাঠাচ্ছে। Thread.sleep(1000) = 1000 millisecond = 1 second wait।

HTTP Protocol

Web server, URL, Request, Response — বিস্তারিত

🌐 HTTP কী?

HTTP (HyperText Transfer Protocol) হলো web-এ data transfer-এর নিয়ম। Client (browser) এবং Server TCP connection করে, তারপর HTTP দিয়ে কথা বলে।

কাজের ধাপ:
① Client-Server TCP connection করে
② Client request পাঠায়
③ Server content দিয়ে respond করে
④ Connection close হয়
Application-layer protocol over TCP. Current version HTTP/1.1 (RFC 2616). Default port: 80.

📦 MIME Type কী?

Server যখন content পাঠায়, সে জানিয়ে দেয় content কী ধরনের — এটাই MIME type। Browser MIME type দেখে বুঝতে পারে কীভাবে content দেখাবে।
Common MIME types:
• text/html — HTML file
• text/plain — Plain text
• image/jpeg — JPEG image
• image/gif — GIF image
• application/postscript — PS doc

🔗 URL Structure

URL = Uniform Resource Locator। প্রতিটি file-এর unique address।

উদাহরণ: http://www.aol.com:80/index.html

Client prefix (http://www.aol.com:80) দেখে বোঝে:
• কোন server-এ যাবে
• কোন port-এ যাবে

Server suffix (/index.html) দেখে:
• static নাকি dynamic content
• file কোথায় আছে
Dynamic content URL example: http://host:8000/cgi-bin/adder?15000&213 — calls executable 'adder' with args 15000 and 213.

📄 Static vs Dynamic Content

Static: Server-এ already stored file। যেমন: HTML, image, audio। Request করলে সরাসরি পাঠিয়ে দেয়।

Dynamic: Request-এর সময় program execute করে content তৈরি। যেমন: CGI script, calculation result।

Bottom line: সব web content একটি file-এর সাথে associated।
Convention: executables in cgi-bin/ directory = dynamic. Everything else = static. All web content is a file managed by server.

📤 HTTP Request Format

HTTP Request = Request Line + Headers + (Body)
Request Line format: <method> <uri> <version>
Methods:
• GET — Static/dynamic content (URI তে arguments)
• POST — Dynamic content (body তে arguments)
• HEAD — GET কিন্তু body নেই
• PUT — Server-এ file লেখা
• DELETE — Server থেকে file মুছা
• OPTIONS — Server/file attributes
• TRACE — Debug (echo request)

📥 HTTP Response Format

HTTP Response = Response Line + Headers + Body
Response Line: <version> <status code> <msg>
Status Codes:
• 200 OK — সফল
• 301 Moved — নতুন URL-এ গেছে
• 403 Forbidden — Permission নেই
• 404 Not Found — File নেই
• 500 Server Error — Server-এ সমস্যা

Important Headers:
• Content-Type — MIME type
• Content-Length — Body size
FeatureHTTP/1.0HTTP/1.1
Connectionপ্রতিটি request-এ নতুন TCP connectionPersistent connection (Keep-Alive)
HOST headerOptionalRequired (mandatory)
CachingBasicAdvanced caching support
Multiple requestsএকটি connection = একটি requestএকটি connection-এ multiple requests

📄 HTTPServerSkeleton.java — Teacher's HTTP Server Code
public class HTTPServerSkeleton {
    static final int PORT = 56666;                          // Line A

    public static void main(String[] args) throws IOException {
        ServerSocket serverConnect = new ServerSocket(PORT);

        // HTML file read করা
        File file = new File("../index.html");               // Line B
        FileInputStream fis = new FileInputStream(file);
        BufferedReader br = new BufferedReader(
            new InputStreamReader(fis, "UTF-8"));              // Line C
        StringBuilder sb = new StringBuilder();
        String line;
        while((line = br.readLine()) != null) sb.append(line).append('\n');
        String content = sb.toString();                        // Line D

        while(true) {
            Socket s = serverConnect.accept();
            BufferedReader in = new BufferedReader(
                new InputStreamReader(s.getInputStream()));   // Line E
            PrintWriter pr = new PrintWriter(s.getOutputStream()); // Line F

            String input = in.readLine();                      // Line G

            if(input != null && input.startsWith("GET")) {    // Line H
                pr.write("HTTP/1.1 200 OK\r\n");               // Line I
                pr.write("Content-Type: text/html\r\n");
                pr.write("Content-Length: " + content.length() + "\r\n");
                pr.write("\r\n");                              // Line J — empty line!
                pr.write(content);                             // Line K
                pr.flush();                                     // Line L
            }
            s.close();                                         // Line M
        }
    }
}
Line A Custom port 56666 ব্যবহার। Browser-এ http://localhost:56666 দিয়ে access করা যাবে।
Line B-D Server start হওয়ার সময় একবারই HTML file পড়া হয়। BufferedReader দিয়ে UTF-8 encoding-এ পড়া হচ্ছে। String content-এ সব HTML রাখা হলো।
Line E-F HTTP তে text-based communication। তাই ObjectStream নয়, BufferedReader (text in) এবং PrintWriter (text out) ব্যবহার।
Line G Browser-এর প্রথম line পড়া (request line)। যেমন: "GET /index.html HTTP/1.1"
Line H startsWith("GET") — GET request check। অন্য method হলে এখানে handle করা হয়নি।
Line I-J HTTP response headers লেখা। প্রতিটি header শেষে \r\n। Line J-তে শুধু \r\n — এটি headers ও body-র মধ্যে mandatory empty line।
Line K-L HTML content body হিসেবে পাঠানো। flush() না করলে data buffer-এ আটকে থাকতে পারে।
Line M HTTP/1.0 style — একটি request serve করেই connection বন্ধ। HTTP/1.1 Keep-Alive হলে বন্ধ করা হতো না।

🔀 Proxy কী?

Proxy হলো client এবং origin server-এর মাঝখানের একটি intermediary (মধ্যস্থতাকারী)।

• Client-এর কাছে: Proxy একটি server মনে হয়
• Server-এর কাছে: Proxy একটি client মনে হয়

কাজ:
• Caching: বারবার একই content server থেকে না নিয়ে proxy তে রেখে দেয়
• Logging: কে কী দেখছে রেকর্ড করে
• Anonymization: client-এর পরিচয় লুকায়
Client ↔ Proxy ↔ Origin Server. Proxy caches responses — when Client B requests foo.html that A already got, proxy serves from cache without hitting origin server again.

Threading in Java

Multi-client server বানানোর পদ্ধতি

🧵 Thread কেন দরকার?

Thread ছাড়া server একটি client serve করার সময় অন্য কোনো client-কে ignore করে। Thread দিয়ে প্রতিটি client-কে আলাদাভাবে একই সময়ে serve করা যায়।

উদাহরণ: Time server — Client A এবং Client B দুজনেই একই সময়ে current time পাচ্ছে।
Without threading: sequential (one at a time). With threading: concurrent (multiple simultaneously). Main thread only accepts connections; Worker threads handle clients.

🔒 Thread Safety

যখন multiple thread একই data access করে, race condition হতে পারে। এটি এড়াতে:

• ConcurrentHashMap — HashMap-এর thread-safe version
• CopyOnWriteArraySet — Set-এর thread-safe version
• synchronized block — একসময় একটিই thread চলবে
• Collections.synchronizedList() — List thread-safe করে
Used in Server.java: ConcurrentHashMap for currentClients, fileMap, fileRequestMap. CopyOnWriteArraySet for offlineClients. synchronized block in FileUploadInfo for writing chunks.

Chunked File Transfer

Assignment-এর upload/download mechanism বিস্তারিত

📌
Assignment Core ConceptFile ছোট ছোট chunk-এ ভেঙে পাঠানো হয়। Server randomly chunk size ঠিক করে, client সেটি follow করে।
📤 File Upload Flow — ধাপে ধাপে
CLIENT
① File name + File size পাঠাও
③ Chunk size ও fileID receive করো
④ File → chunks-এ ভাগ করো
⑤ Chunk পাঠাও (একটি একটি করে)
⑦ ACK পেলে পরের chunk পাঠাও
⑧ শেষে "completed" message পাঠাও
⟷
SERVER
② Buffer check: usedBuffer + newFile ≤ MAX_BUFFER_SIZE?
③ Random chunk size generate করো, fileID তৈরি করো
⑥ Chunk receive করো → ACK পাঠাও
⑨ Total bytes == file size? → Save করো
⑩ Success/Failure message পাঠাও
⚠️
Important RuleUpload: Server ACK wait করে (reliable)। Download: Server ACK wait করে না, সরাসরি MAX_CHUNK_SIZE দিয়ে পাঠায় (fast)।
💡 Chunk Calculation Example
// Example: File size = 1040 KB, Chunk size = 100 KB
// Number of chunks = ceil(1040 / 100) = 11
// First 10 chunks: 100 KB each
// Last chunk: 40 KB

// ClientUtil.java — actual upload code:
byte[] buffer = new byte[fileChunkSize];         // chunk size buffer তৈরি
int bytesRead = fileInputStream.read(buffer);    // প্রথম chunk পড়া

while(bytesRead != -1) {                         // যতক্ষণ file আছে
    byte[] chunk = new byte[bytesRead];           // exact size chunk
    System.arraycopy(buffer, 0, chunk, 0, bytesRead); // copy bytes
    out.writeObject(chunk);                       // server-এ পাঠাও
    
    String ack = (String) in.readObject();         // ACK wait করো
    if(!ack.contains("received")) break;          // error হলে বন্ধ
    
    bytesRead = fileInputStream.read(buffer);     // পরের chunk পড়া
}
out.writeObject("File upload completed for file ID: " + fileId);

Easy থেকে Advanced — সব level-এর প্রশ্ন

💡
How to useপ্রতিটি প্রশ্নে click করলে উত্তর দেখাবে। নিজে আগে চেষ্টা করো!
Easy What is a Socket? What information does a socket need? ▼
Socket হলো দুটো network application-এর মধ্যে একটি connection। একটি socket জানে: Remote IP (অন্য পক্ষের IP), Remote Port, Local Port। Socket-এর দুটো buffer আছে: Input Buffer (receive করা data) ও Output Buffer (পাঠানোর জন্য data)।

A socket represents a single TCP connection between two network applications. Number of connections = number of sockets. Each socket needs: Remote IP, Remote Port, Local Port, plus input and output buffers.

Easy What is the difference between ServerSocket and Socket in Java? ▼
ServerSocket হলো server-এর "welcome door" — এটি শুধু client-এর connection গ্রহণ করে, data transfer করে না। Socket হলো actual connection — এটি দিয়ে data পাঠানো ও পড়া যায়।

ServerSocket: Listens on a port for incoming connections. Calls accept() to wait. Returns a Socket when a client connects.
Socket: Represents an active connection. Has input/output streams for data transfer. Created on client side with new Socket(host, port) or on server side from accept().

Easy What does accept() do? Is it blocking? ▼
accept() হলো একটি blocking call — কোনো client connect না হওয়া পর্যন্ত execution এখানেই থামে। Client connect হলে একটি Socket object return করে।

Yes, accept() is a blocking call. The server thread pauses at this line until a client connects. When a connection arrives, it returns a new Socket object representing that specific client connection. The ServerSocket continues to listen for more connections.

Easy What is HTTP? What port does it use by default? ▼
HTTP (HyperText Transfer Protocol) হলো web-এ data transfer-এর protocol। এটি TCP-র উপর কাজ করে। Default port হলো 80। Current version HTTP/1.1 (RFC 2616)।

HTTP (HyperText Transfer Protocol) is the application-layer protocol used by web clients and servers to communicate. It runs over TCP. Default port: 80. HTTPS uses port 443. Current common version: HTTP/1.1.

Easy What are the HTTP methods? Briefly explain each. ▼
GET: Static/dynamic content retrieve (arguments URI-তে) — সবচেয়ে বেশি ব্যবহৃত (99%)। POST: Dynamic content (arguments body-তে)। HEAD: GET-এর মতো কিন্তু body নেই। PUT: Server-এ file লেখা। DELETE: Server থেকে file মুছা। OPTIONS: Server/file attributes। TRACE: Debug (request echo করে)।

GET: Retrieve content (workhorse, 99%). POST: Submit data in body. HEAD: Like GET, no response body. PUT: Write file to server. DELETE: Remove file. OPTIONS: Get attributes. TRACE: Echo request for debugging.

Easy What is MIME type? Give 3 examples. ▼
MIME (Multipurpose Internet Mail Extensions) type হলো content-এর ধরন জানানোর উপায়। Server response-এ Content-Type header-এ MIME type পাঠায়, browser সেটি দেখে বুঝতে পারে কীভাবে content দেখাবে।

MIME type tells the client what kind of content is in the response body. Examples: text/html (HTML doc), image/jpeg (JPEG image), text/plain (plain text), image/gif (GIF), application/postscript (PostScript).

Medium Why do we need threading in a server? Explain with the time server example. ▼
Threading ছাড়া, server-এর main loop একটি client-এর while(true) loop-এ আটকে থাকবে। দ্বিতীয় client connect করলে accept() কখনো reach হবে না। Thread দিয়ে প্রতিটি client-কে আলাদা thread-এ serve করা হয়, main thread শুধু accept() করতে থাকে।

Without threading: Server's main loop gets stuck in a while(true) loop serving Client 1 — Client 2 never gets accepted.

With threading (time server): Main thread calls accept() → gets socket → creates new Worker(socket) → calls worker.start() → immediately loops back to accept(). Worker handles Client 1 in background. Now both Client.java and Client2.java receive time simultaneously.

Medium Explain the difference between HTTP/1.0 and HTTP/1.1. ▼
HTTP/1.0: প্রতিটি request-এর জন্য নতুন TCP connection তৈরি ও বন্ধ করতে হয়।
HTTP/1.1: Persistent connection — একই TCP connection-এ multiple request। Connection: Keep-Alive header দিয়ে জানানো হয়। Host header mandatory। Better caching।

HTTP/1.0: New TCP connection for each request/response.
HTTP/1.1: Persistent connections (Connection: Keep-Alive) — multiple transactions over same TCP. HOST header is required. Enhanced caching with ETag, Cache-Control headers. Chunked transfer encoding supported.

Medium In the assignment, explain the file upload buffer check mechanism. ▼
Client file upload শুরুর আগে file name ও size পাঠায়। Server দেখে: (usedBufferSize + newFileSize) > MAX_BUFFER_SIZE? যদি বেশি হয় — upload reject। না হলে — random chunk size generate করে (MIN ও MAX এর মধ্যে), fileID তৈরি করে, client-কে জানায়।

Before upload starts:
1. Client sends: fileName, fileSize
2. Server checks: usedBufferSize + newFileSize ≤ MAX_BUFFER_SIZE (500MB)
3. If exceeds: reject with error message
4. If OK: generate random chunkSize between MIN_CHUNK_SIZE (10) and MAX_CHUNK_SIZE (100KB), create a unique fileID, send both to client

Medium What is the role of ObjectOutputStream and ObjectInputStream? Why must ObjectOutputStream be created FIRST? ▼
ObjectOutputStream হলো data পাঠানোর channel (writeObject() ব্যবহার)। ObjectInputStream হলো data পড়ার channel (readObject() ব্যবহার)।

ObjectOutputStream প্রথমে তৈরি করতে হয় কারণ OOS তৈরির সময় সে stream header পাঠায়। OIS তৈরির সময় সে এই header পড়ে। যদি দুই পাশে OOS-এর আগে OIS তৈরি করা হয়, deadlock হবে।

ObjectOutputStream: Serializes Java objects and writes to socket's output stream.
ObjectInputStream: Reads and deserializes objects from socket's input stream.

Order matters: ObjectOutputStream must be created before ObjectInputStream on BOTH sides, because new ObjectOutputStream() writes a stream header, and new ObjectInputStream() reads that header. Creating OIS first on both sides causes deadlock — each waits for the other's header.

Medium Explain what happens when a client connects to a server for the first time in the assignment. ▼
① Server accept() করে নতুন Worker thread তৈরি করে। ② Server "Enter username" message পাঠায়। ③ Client username পাঠায়। ④ Server check করে: username ইতোমধ্যে currentClients-এ আছে? থাকলে "closing" message দিয়ে disconnect। না থাকলে: directory তৈরি করে (প্রথমবার হলে), currentClients-এ add করে, "Welcome" message পাঠায়। ⑤ Client menu দেখে।

1. New Worker thread spawned by server
2. Worker sends "Enter username" prompt
3. Client sends username string
4. Server checks currentClients.containsKey(username)
5. If duplicate: sends "closing" → closes connection
6. If new: creates Server/ServerFiles/{username}/ directory (if first time), adds to currentClients, removes from offlineClients, sends welcome message
7. Client enters menu loop

Medium What is a Proxy server? What are its uses? ▼
Proxy হলো client এবং origin server-এর মাঝখানের intermediary। Client-এর কাছে proxy = server। Server-এর কাছে proxy = client। ব্যবহার: ① Caching (বারবার একই content server থেকে না নিয়ে cache থেকে দেওয়া), ② Logging, ③ Anonymization (client-এর পরিচয় লুকানো)।

A proxy sits between client and origin server, acting as server to the client and as client to the server.

Uses:
• Caching: Store responses locally — Client B gets foo.html from proxy cache without hitting origin server again
• Logging: Record all requests passing through
• Anonymization: Hide client's real IP from origin server
• Content filtering: Block certain content

Hard Why does the assignment use ConcurrentHashMap instead of HashMap? Explain with a scenario. ▼
Multiple thread একই সময়ে HashMap-এ write করলে data corruption বা ConcurrentModificationException হতে পারে। উদাহরণ: Thread A (Client alice) ও Thread B (Client bob) একই সময়ে fileMap.put() করলে HashMap crash করতে পারে। ConcurrentHashMap thread-safe — একাধিক thread একসাথে safely পড়তে ও লিখতে পারে।

Problem with HashMap: Not thread-safe. If Thread-1 (handling alice) and Thread-2 (handling bob) both call fileMap.put() simultaneously, internal state can corrupt → ConcurrentModificationException or data loss.

ConcurrentHashMap: Divides the map into segments, locking only the relevant segment for each write. Reads are lock-free. Multiple threads can safely read and write without explicit synchronization.

Same reason for CopyOnWriteArraySet for offlineClients: writes create a new copy of the array — reads are never blocked.

Hard Explain the complete file download flow in the assignment. How is it different from upload? ▼
Download flow: Client file ID পাঠায় → Server validate করে → Valid হলে file name পাঠায় → MAX_CHUNK_SIZE (100KB) দিয়ে chunks পাঠায় → শেষে "download completed" message পাঠায়।

Upload-এর সাথে পার্থক্য: Upload-এ প্রতিটি chunk-এর পর ACK wait করা হয়, কিন্তু download-এ ACK wait করা হয় না — directly সব chunk পাঠিয়ে দেয়। Download আরও fast কিন্তু less reliable।

Download flow:
1. Client sends fileId to server
2. Server validates: exists in fileMap? accessible (own file or other's public)?
3. If invalid: sends error message
4. If valid: sends "This is valid file." → sends fileName → starts sending chunks
5. Uses MAX_CHUNK_SIZE for all chunks (no random)
6. No ACK wait — sends chunks continuously
7. Sends "download completed" string at end

Key difference from upload: Upload is ACK-driven (reliable, slower). Download has no ACK (fire-and-forget, faster). Client just writes bytes to FileOutputStream until it receives the "download completed" signal.

Hard What happens if a client disconnects mid-upload? How does the server handle it? ▼
Client disconnect হলে Worker thread-এর readObject() একটি IOException বা SocketException throw করবে। Server এই exception catch করে incomplete file-এর সব chunks discard করে। FileUploadInfo object থেকে data মুছে ফেলে, usedBufferSize update করে। FileMapStorage.txt-এ কিছু লেখা হয় না (saveFileToServerStorage() call হয়নি তাই)।

When client disconnects mid-upload:
1. in.readObject() in Worker thread throws SocketException or IOException
2. Worker's run() catches the exception
3. Incomplete FileUploadInfo is discarded — chunks never assembled
4. File never written to disk (saveFileToServerStorage not called)
5. FileMapStorage.txt not updated
6. Worker removes client from currentClients, adds to offlineClients
7. usedBufferSize must be decremented (cleanup)

Key: isComplete = false means the upload never completed.

Hard Explain file request (unicast vs broadcast) in the assignment. ▼
Client file request করলে: description ও recipient পাঠায়। Server request ID generate করে, FileRequest object তৈরি করে fileRequestMap-এ রাখে।

Unicast: Recipient specific username হলে — শুধু সেই client-এর message queue-তে add। Broadcast: Recipient "ALL" হলে — currentClients + offlineClients সবার কাছে পাঠায়।

কেউ request fulfill করলে: uploader file upload করার সময় valid requestId দেয় → automatically public file → server request করা client-কে message পাঠায়। Multiple clients একই request fulfill করতে পারে।

File Request flow:
1. Client sends: description + recipient name (or "ALL")
2. Server generates unique requestID, creates FileRequest object, adds to fileRequestMap

Unicast: If recipient = specific username → add to that client's unread messages (online or offline)
Broadcast: If recipient = "ALL" → iterate all clients (currentClients + offlineClients), add message to each

Fulfilling: When uploader selects "Yes" to upload as request response → must provide valid requestID → file automatically set to Public → server sends notification message to original requester → multiple fulfillers allowed

Hard Explain the HTTP request format with a complete GET request example. ▼
HTTP Request = Request Line + Headers + empty line + (optional body)।

Request Line format: METHOD URI HTTP/VERSION।
GET request-এ body থাকে না — arguments URI-তে যায়।
GET /test.html HTTP/1.1          ← Request line: method URI version
Accept: */*                       ← Headers শুরু
Accept-Language: en-us
Accept-Encoding: gzip, deflate
User-Agent: Mozilla/4.0
Host: euro.ecom.cmu.edu           ← HTTP/1.1-এ HOST mandatory
Connection: Keep-Alive
                                  ← Empty line (CRLF) = headers শেষ

Key points: Request line is METHOD URI HTTP/VERSION. Headers are Name: Value pairs. Empty CRLF line terminates headers. GET has no body — arguments go in URI as query string after ?.

Advanced Write a complete threaded server that handles multiple clients and broadcasts a message to all connected clients. ▼
Broadcast করতে server সব connected client-এর ObjectOutputStream রাখতে হবে (ConcurrentHashMap-এ)। নতুন client connect হলে সে map-এ add হবে। Broadcast-এর সময় সব map-এর values iterate করে writeObject() করতে হবে।
import java.net.*; import java.io.*; import java.util.concurrent.*;

public class BroadcastServer {
    // Shared map: clientName → their ObjectOutputStream
    static ConcurrentHashMap<String, ObjectOutputStream> clients = 
        new ConcurrentHashMap<>();

    public static void broadcast(String msg) {
        clients.forEach((name, out) -> {
            try { out.writeObject(msg); } 
            catch (IOException e) { clients.remove(name); }
        });
    }

    public static void main(String[] args) throws Exception {
        ServerSocket ss = new ServerSocket(6666);
        while(true) {
            Socket s = ss.accept();
            new Thread(() -> {
                try {
                    ObjectOutputStream out = new ObjectOutputStream(s.getOutputStream());
                    ObjectInputStream in = new ObjectInputStream(s.getInputStream());
                    String name = (String) in.readObject();
                    clients.put(name, out);
                    broadcast(name + " joined!");
                    while(true) {
                        String msg = (String) in.readObject();
                        broadcast(name + ": " + msg);
                    }
                } catch(Exception e) { e.printStackTrace(); }
            }).start();
        }
    }
}
Advanced In CommonFunctionUtility.java, explain the byte-by-byte file parsing. Why not use Scanner or BufferedReader? ▼
fileToHashMap() FileInputStream দিয়ে byte-by-byte পড়ে। যখন '\n' পায়, তখন buffer-এ জমা bytes দিয়ে String তৈরি করে '|' দিয়ে split করে। এটি low-level approach।

Scanner বা BufferedReader ব্যবহার না করার কারণ হতে পারে: নিজে socket-level byte handling practice, অথবা specific encoding control। Production-এ Scanner/BufferedReader ব্যবহার করাই ভালো।

The method reads one byte at a time using FileInputStream.read(). It buffers bytes in an ArrayList<Byte>. On encountering '\n', it converts the buffer to a byte[], creates a String, splits by | (pipe), and adds to result.

Why not BufferedReader? This is a manual/educational approach demonstrating low-level I/O. BufferedReader would be simpler: br.readLine() returns each line, then line.split("\\|"). The manual approach gives explicit byte-level control similar to what happens in actual socket streams.

Advanced Why does FileUploadInfo use Collections.synchronizedList() for chunksList? ▼
chunksList-এ multiple thread access করতে পারে — Worker thread chunk add করে, অন্য thread চাইলে পড়তে পারে। Regular ArrayList thread-safe নয় — একসাথে add ও iterate করলে ConcurrentModificationException হতে পারে। Collections.synchronizedList() একটি wrapper তৈরি করে যেখানে প্রতিটি operation synchronized।

saveFileToServerStorage()-এ synchronized(chunksList) block ব্যবহার করা হয়েছে কারণ iteration-এর সময় external synchronization লাগে।

chunksList stores file chunks as byte[] arrays. In a multi-threaded server, a Worker thread adds chunks during upload, while another operation could potentially read the list simultaneously.

Collections.synchronizedList(new ArrayList<>()) wraps ArrayList so each individual operation (add, size, get) is synchronized.

However, iteration is not automatically safe — that's why saveFileToServerStorage() uses synchronized(chunksList) { for(byte[] chunk : chunksList)... } — to hold the lock during the entire iteration, preventing concurrent modification.

Advanced Describe what initiationOfflineClients() and initiationFileMapStorage() do and why they are needed. ▼
এই দুটো method server restart-এর পর আগের state restore করে।

initiationOfflineClients(): Server/ServerFiles/ directory-র সব subdirectory scan করে। প্রতিটি directory একটি client-এর username। এদের offlineClients set-এ add করে। এটি না থাকলে server restart করলে সব previous client-এর record হারিয়ে যাবে।

initiationFileMapStorage(): FileMapStorage.txt পড়ে, parse করে, প্রতিটি line থেকে FileUploadInfo object তৈরি করে fileMap-এ add করে। এটি না থাকলে server restart করলে কেউ আগে upload করা file download করতে পারবে না।

Why needed: Server can restart. These methods restore state from persistent storage.

initiationOfflineClients(): Scans Server/ServerFiles/ for subdirectories. Each subdirectory = a client who connected at least once. Adds all to offlineClients. Without this, after restart, the server wouldn't know about previous clients.

initiationFileMapStorage(): Reads pipe-delimited FileMapStorage.txt via CommonFunctionUtility.fileToHashMap(). For each row (7 fields), creates FileUploadInfo object and puts in fileMap. Without this, all uploaded files would be inaccessible after restart since fileMap would be empty.

Advanced Analyze a potential deadlock scenario in socket programming and how to avoid it. ▼
Deadlock scenario: Server এবং Client উভয়ই readObject() call করছে, কেউ writeObject() করছে না। দুজনেই অপরের message-এর জন্য অপেক্ষা করছে — এটি deadlock।

আরেকটি: OIS তৈরির সমস্যা। দুই পাশে ObjectInputStream আগে তৈরি করলে, OIS তার header পড়তে চাইবে কিন্তু কেউই header পাঠায়নি — deadlock।

Scenario 1 — Read-Read deadlock:
Server: in.readObject() → waiting for client
Client: in.readObject() → waiting for server
Both blocked forever. Fix: agree on protocol — one side writes first.

Scenario 2 — OIS initialization deadlock:
Side A: new ObjectInputStream() → reads stream header, blocks
Side B: new ObjectInputStream() → reads stream header, blocks
Neither creates ObjectOutputStream to send the header!
Fix: Always create ObjectOutputStream first on BOTH sides.

Scenario 3 — Buffer full: TCP send buffer fills up if receiver doesn't read. Fix: use separate reader thread.

Advanced Write code to implement a simple HTTP server that serves different responses for GET and returns 404 for unknown paths. ▼
HTTP server-এ: request line parse করে URI বের করা, URI অনুযায়ী response দেওয়া। Unknown path হলে 404 response।
import java.io.*; import java.net.*;

public class SimpleHTTPServer {
    public static void main(String[] args) throws Exception {
        ServerSocket ss = new ServerSocket(8080);
        while(true) {
            Socket s = ss.accept();
            BufferedReader in = new BufferedReader(
                new InputStreamReader(s.getInputStream()));
            PrintWriter out = new PrintWriter(s.getOutputStream());
            
            String requestLine = in.readLine();
            if(requestLine == null) { s.close(); continue; }
            
            String[] parts = requestLine.split(" ");
            String method = parts[0];
            String uri = parts.length > 1 ? parts[1] : "/";
            
            if(method.equals("GET")) {
                if(uri.equals("/") || uri.equals("/index.html")) {
                    String body = "<html><h1>Welcome!</h1></html>";
                    out.print("HTTP/1.1 200 OK\r\nContent-Type: text/html\r\n");
                    out.print("Content-Length: "+body.length()+"\r\n\r\n"+body);
                } else {
                    String body = "<html><h1>404 Not Found</h1></html>";
                    out.print("HTTP/1.1 404 Not Found\r\nContent-Type: text/html\r\n");
                    out.print("Content-Length: "+body.length()+"\r\n\r\n"+body);
                }
            }
            out.flush(); s.close();
        }
    }
}
