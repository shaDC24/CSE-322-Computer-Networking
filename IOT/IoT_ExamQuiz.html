🌐 MQTT & IoT Fundamentals

Q1What does MQTT stand for? In one sentence, what is it?▼
MQTT = Message Queuing Telemetry Transport. এটা একটা lightweight publish-subscribe messaging protocol যা IoT devices এ low-bandwidth network এ real-time communication এর জন্য ব্যবহার হয়।
Q2What is an MQTT Broker? Name the broker used in the assignment.▼
Broker হলো একটা central server যে Publisher থেকে message receive করে এবং সেই topic এর Subscriber দের কাছে deliver করে। Publisher এবং Subscriber কখনো সরাসরি communicate করে না।

Assignment এ ব্যবহৃত broker: broker.hivemq.com (public, free)
Q3What is an MQTT Topic? What is the topic used in this assignment?▼
Topic হলো একটা string যেটা message এর destination address হিসেবে কাজ করে। এটা hierarchical, slash (/) দিয়ে levels আলাদা করা হয়।

Assignment এ topic: buet/cse/2105123/led
Structure: university / department / student_id / device
Q4What is the difference between Publisher and Subscriber in MQTT?▼
Publisher: কোনো topic এ message পাঠায় (send করে)। এই assignment এ Python code হলো Publisher।

Subscriber: কোনো topic এ interest register করে রাখে এবং সেই topic এ message আসলে receive করে। এই assignment এ ESP32 হলো Subscriber।
Q5What port does MQTT use? What does port 8883 mean?▼
Port 1883 — Standard MQTT, unencrypted (plaintext TCP). এই assignment এ এটাই ব্যবহার হয়েছে।

Port 8883 — MQTT over TLS/SSL, encrypted connection। Real production systems এ এটা ব্যবহার হয় security এর জন্য।
Q6What is QoS in MQTT? What level is used here and why might messages be dropped?▼
QoS (Quality of Service) হলো message delivery guarantee এর level:
• QoS 0 = "fire and forget" — no guarantee
• QoS 1 = at least once delivered
• QoS 2 = exactly once delivered

এই assignment এ QoS 0 (default) ব্যবহার হয়েছে। তাই assignment এ বলা হয়েছে "one or two messages may be dropped" — QoS 0 তে delivery guarantee নেই।

🔌 ESP32 Code Questions

Q7What does client.loop() do in the ESP32 loop() function? What happens if it's removed?▼
client.loop() তিনটা কাজ করে:
1. MQTT TCP connection alive রাখে (PINGREQ পাঠায়)
2. Broker থেকে আসা incoming messages check করে
3. Message আসলে callback() function trigger করে

Remove করলে: MQTT connection timeout হবে, কোনো message receive হবে না, LED কখনো respond করবে না।
Q8Why is client.setCallback(callback) called in setup()? What does it do?▼
এটা MQTT library কে বলে দেয় যে subscribe করা topic এ কোনো message আসলে কোন function টা call করতে হবে। এখানে আমাদের callback() function এর pointer দেওয়া হয়েছে।

ছাড়া দিলে message আসলে কোনো action হবে না — LED কখনো ON/OFF হবে না।
Q9Why does the callback() function receive byte* payload instead of a String directly? How is it converted?▼
MQTT protocol raw bytes transport করে, null-terminated string না। তাই payload একটা byte array হিসেবে আসে।

Conversion: 
String message = "";
for (unsigned int i = 0; i < length; i++) {
    message += (char)payload[i];  // byte → char → String
}
Q10What is the role of reconnect() function? Why does it use a while loop?▼
reconnect() MQTT broker এ connect করে এবং topic subscribe করে। Network বা broker temporarily unavailable থাকলে এটাই reconnection handle করে।

while loop কেন? if দিলে একবার fail করলে চেষ্টা বন্ধ হয়ে যেত। while দিয়ে connected না হওয়া পর্যন্ত প্রতি 5 সেকেন্ড পর পর retry হয়।
Q11What does pinMode(ledPin, OUTPUT) do? What would happen without it?▼
PIN 2 কে OUTPUT mode এ configure করে। Default এ GPIO pins INPUT mode এ থাকে।

Without it: digitalWrite() কাজ করবে না — pin এ কোনো voltage change হবে না, LED কখনো জ্বলবে না।
Q12What are the two libraries included in the ESP32 code and what does each do?▼
#include <WiFi.h> — ESP32 কে WiFi network এ connect করার জন্য। Built-in Arduino library।

#include <PubSubClient.h> — MQTT protocol implement করার জন্য। এটা manually install করতে হয় (Library Manager → PubSubClient)।
Q13Why is WiFiClient espClient passed to PubSubClient client(espClient)?▼
MQTT হলো application-layer protocol যেটা TCP এর উপর চলে। PubSubClient কে MQTT handle করতে হলে একটা TCP socket দরকার।

WiFiClient সেই TCP socket provide করে। ESP32 এর WiFi stack ব্যবহার করে internet access করে। তাই espClient টা PubSubClient এর constructor এ দিতে হয়।
Q14What is the WiFi SSID used in Wokwi? Why is the password empty?▼
SSID: "Wokwi-GUEST" — এটা Wokwi simulator এর built-in virtual WiFi network।

Password empty ("") কারণ এটা একটা open guest network, কোনো authentication লাগে না। Real hardware এ actual WiFi credentials দিতে হয়।

🐍 Python Code Questions

Q15What Python library is used for MQTT? How is it installed and imported?▼
Library: paho-mqtt

Install: pip install paho-mqtt

Import: import paho.mqtt.client as mqtt
Q16What is client.loop_start() in Python? How is it different from ESP32's client.loop()?▼
loop_start() একটা background thread এ MQTT loop চালায়। এর ফলে main thread input() তে block থাকলেও MQTT messages receive হয় এবং on_message() fire করে।

ESP32 এর client.loop(): manually প্রতিটা loop() iteration এ call করতে হয় — blocking, single-threaded।

Python এর loop_start(): একবার call করলেই background এ চলতে থাকে — non-blocking।
Q17What does msg.payload.decode() do in Python's on_message()?▼
msg.payload হলো bytes object (raw binary data)। .decode() এটাকে UTF-8 string এ convert করে।

Without decode: b'LED is ON' (bytes literal)
After decode: 'LED is ON' (regular string)

Comparison বা print করতে হলে string এ convert করতে হয়।
Q18In two-way communication, why is client.subscribe() called inside on_connect() in Python instead of after client.connect()?▼
on_connect() এর ভেতরে subscribe করলে automatic re-subscription পাওয়া যায়। Network drop হলে broker reconnect হওয়ার সময় on_connect আবার call হয় এবং subscription আবার setup হয়।

সরাসরি connect() এর পরে subscribe করলে reconnection এ subscription হারিয়ে যায়।

🔄 Two-Way Communication

Q19In two-way communication, how many topics are needed and what is each one for?▼
2 topics দরকার:

2. buet/cse/2105123/led/status — Status topic। ESP32 publishes ("LED is ON"/"LED is OFF"), Python subscribes।

দুটো আলাদা topic দরকার কারণ প্রতিটা topic এর direction আলাদা।
Q20What single line was added inside ESP32's callback() for two-way communication?▼
LED state change করার পর, status topic এ publish করার line যোগ হয়েছে:
// After digitalWrite(ledPin, HIGH):
client.publish(statusTopic, "LED is ON");

// After digitalWrite(ledPin, LOW):
client.publish(statusTopic, "LED is OFF");

💡 Circuit Questions

Q21Why is a resistor used in the LED circuit? What is its value?▼
LED এর নিজস্ব কোনো resistance নেই। Resistor ছাড়া সরাসরি connect করলে অতিরিক্ত current প্রবাহিত হবে এবং LED পুড়ে যাবে (এবং ESP32 pin ও damage হতে পারে)।

Resistor current কে safe level এ limit রাখে।

Assignment এ value: 1000Ω (1kΩ)
Q22What does digitalWrite(ledPin, HIGH) physically do to the LED?▼
PIN 2 এ 3.3V voltage output করে। এতে circuit এ current flow হয়: PIN2 → Resistor → LED Anode → LED Cathode → GND। Current flow হলে LED জ্বলে।

digitalWrite(ledPin, LOW) → 0V → no current → LED off।
Q23What is Wokwi? What is the WiFi network name available in Wokwi?▼
Wokwi হলো একটা online electronics simulator যেখানে Arduino, ESP32 ইত্যাদি hardware কে virtually simulate করা যায়। Real device ছাড়াই কোড test করা যায়।

Wokwi এর built-in WiFi network: Wokwi-GUEST (no password, real internet access আছে)

📤 Output Question
Consider the following Python code. User runs it and types: y → Enter → n → Enter → q → Enter
import paho.mqtt.client as mqtt broker = "broker.hivemq.com" topic = "buet/cse/2105123/led" client = mqtt.Client() client.connect(broker) while True: user_input = input("Enter y/n/q: ") if user_input == 'y': client.publish(topic, "ON") elif user_input == 'n': client.publish(topic, "OFF") elif user_input == 'q': break
Q: What happens on the ESP32 side for each input? Trace the sequence.
Reveal Answer ▼
Step-by-step trace:

1. User types y → Python publishes "ON" to broker → Broker delivers to ESP32 → callback() fires → message == "ON" → digitalWrite(2, HIGH) → LED turns ON 💡

2. User types n → Python publishes "OFF" → ESP32 callback → message == "OFF" → digitalWrite(2, LOW) → LED turns OFF ⚫

3. User types q → break → Python program exits. ESP32 is unaffected — it keeps running and listening on the topic.
🐛 Bug Question
A student writes the following ESP32 loop() function. The ESP32 connects to WiFi and MQTT successfully, but the LED never responds to any Python command.
void loop() { if (!client.connected()) { reconnect(); } // student forgot something here }
Q: What is the bug? Why does the LED not respond? What is the fix?
Reveal Answer ▼
Bug: client.loop() missing!

কেন LED respond করে না: client.loop() ছাড়া MQTT library কোনো incoming messages process করে না। Message broker থেকে আসলেও ESP32 এর TCP buffer এ পড়ে থাকে, কিন্তু callback() কখনো fire হয় না। Connection ও eventually timeout হয়।

Fix:
void loop() { if (!client.connected()) { reconnect(); } client.loop(); // ← THIS WAS MISSING }
🤔 Why Question
A student modifies the reconnect() function as follows. Everything seems to work, but after a WiFi dropout and reconnect, the LED stops responding to commands forever.
void reconnect() { while (!client.connected()) { if (client.connect("ESP32_Wokwi_LED")) { Serial.println("connected"); // student removed client.subscribe(topic); } else { delay(5000); } } }
Q: Why does the LED stop responding after reconnection? What is the fix?
Reveal Answer ▼
কারণ: MQTT subscriptions disconnect হলে হারিয়ে যায়। Broker disconnected client এর subscription list মুছে দেয়।

প্রথমবার setup() → reconnect() → subscribe() সব ঠিক ছিল। কিন্তু WiFi dropout এর পর reconnect হয়েছে কিন্তু subscribe() আর call হয়নি। তাই broker ESP32 কে ওই topic এর subscriber মনে করছে না — কোনো message deliver করছে না।

Fix: reconnect() এ সবসময় connect এর পর subscribe করতে হবে:
client.subscribe(topic); // ← always re-subscribe after reconnect
📤 Output Question
Two students — Alice (ID: 2105001) and Bob (ID: 2105002) — both run the original one-way Python code. Alice uses topic "buet/cse/2105001/led" and Bob uses "buet/cse/2105002/led". Alice types 'y'. Both ESPs are subscribed correctly.
Q: What happens? Whose LED turns ON?
Reveal Answer ▼
Only Alice's LED turns ON.

কারণ: Alice এর Python "buet/cse/2105001/led" topic এ "ON" publish করে। Broker শুধু এই exact topic এর subscribers কে deliver করে।

Bob এর ESP32 subscribe করা আছে "buet/cse/2105002/led" এ — সেটা সম্পূর্ণ আলাদা topic। Bob এর LED unaffected থাকে।

এটাই hierarchical topic এর purpose — প্রতিটা student এর unique student ID দিয়ে তারা একই public broker ব্যবহার করেও একে অপরের device interfere করতে পারে না।
🐛 Bug Question — Python
A student writes this Python two-way code. Commands send successfully (y/n work), but the ESP32 status replies never appear on screen.
import paho.mqtt.client as mqtt broker = "broker.hivemq.com" cmdTopic = "buet/cse/2105123/led" statusTopic = "buet/cse/2105123/led/status" def on_message(client, userdata, msg): print(f"[Status] {msg.payload.decode()}") client = mqtt.Client() client.on_message = on_message client.connect(broker) client.loop_start() while True: u = input("y/n/q: ") if u == 'y': client.publish(cmdTopic, "ON") elif u == 'n': client.publish(cmdTopic, "OFF") elif u == 'q': break
Q: What is the bug? Why don't status messages appear?
Reveal Answer ▼
Bug: client.subscribe(statusTopic) is missing!

on_message callback ঠিকমতো define করা আছে এবং register ও করা আছে। কিন্তু Python কখনো statusTopic subscribe করেনি। Broker জানে না যে এই Python client status topic এর messages চায়।

Fix: connect() এর পর subscribe করতে হবে:
client.connect(broker) client.subscribe(statusTopic) # ← THIS WAS MISSING client.loop_start()
অথবা best practice হলো on_connect() callback এর ভেতরে subscribe করা।
🔮 Predict Question
Consider the ESP32 callback function below. User sends "on" (lowercase) from Python.
void callback(char* topic, byte* payload, unsigned int length) { String message; for (unsigned int i=0; i<length; i++) message+=(char)payload[i]; if (message == "ON") digitalWrite(ledPin, HIGH); else if (message == "OFF") digitalWrite(ledPin, LOW); }
Q: What happens to the LED? Why? How would you fix it to handle both "on" and "ON"?
Reveal Answer ▼
LED does NOT change state.

কারণ: Arduino এর String comparison case-sensitive। "on" == "ON" → false। Neither if nor else-if condition matches, so digitalWrite() কখনো call হয় না। LED যে state এ ছিল সেখানেই থাকবে।

Fix 1 — Convert to uppercase before comparing:
message.toUpperCase(); // "on" → "ON" if (message == "ON") ...
Fix 2 — Handle both cases explicitly:
if (message == "ON" || message == "on") ...
🤔 Why/What Question
The assignment note says: "Because we are using a public MQTT broker, one or two messages may be dropped."
Q: Explain WHY messages can be dropped. What concept causes this? How could it be fixed?
Reveal Answer ▼
কারণ: QoS 0 (Quality of Service level 0)

MQTT এর default QoS level হলো 0 যাকে "fire and forget" বলে। Publisher message পাঠায়, কোনো acknowledgment নেয় না এবং কোনো retry হয় না। Network congestion বা temporary broker load এ message drop হতে পারে।

Public broker (HiveMQ free) তে অনেক users থাকে, load বেশি — তাই drop এর probability বাড়ে।

Fix: QoS 1 বা QoS 2 ব্যবহার করা:
• QoS 1 = "at least once" — broker acknowledgment পাঠায়, না পেলে retry
• QoS 2 = "exactly once" — guaranteed, no duplicates

Python: client.publish(topic, "ON", qos=1)
ESP32: client.subscribe(topic, 1)

T/F 2"client.loop() in the Arduino loop() is optional — it only improves performance."
TTrue
FFalse
FALSE. client.loop() বাধ্যতামূলক। ছাড়া দিলে MQTT কোনো incoming message process করে না এবং connection timeout হয়। এটা ছাড়া কোনো message কখনো receive হবে না।
T/F 3"In the two-way version, ESP32 subscribes to both the command topic AND the status topic."
TTrue
FFalse
FALSE. ESP32 শুধু command topic (buet/.../led) subscribe করে। Status topic এ ESP32 publish করে (reply দেয়)। Subscribe করলে ESP32 নিজের reply নিজে receive করত — এটার কোনো মানে নেই।
T/F 4"MQTT topic comparison is case-sensitive. 'LED' and 'led' are different topics."
TTrue
FFalse
TRUE. MQTT topics সম্পূর্ণ case-sensitive। buet/cse/2105123/LED এবং buet/cse/2105123/led দুটো আলাদা topic। Publisher আর Subscriber এর topic exactly same হতে হবে।
T/F 5"WiFiClient espClient is needed because MQTT runs on top of TCP/IP."
TTrue
FFalse
TRUE. MQTT একটা application-layer protocol। এর নিচে TCP transport দরকার। WiFiClient সেই TCP socket দেয়। PubSubClient constructor এ espClient pass করা হয় এই কারণেই।
T/F 6"Removing the 1kΩ resistor from the circuit would make the LED brighter."
TTrue
FFalse
FALSE (partially true but misleading). Technically বেশি current এ LED briefly brighter হবে — কিন্তু সাথে সাথে LED পুড়ে যাবে (burnout)। Resistor current protect করে। তাই practical answer হলো: LED ও destroy হবে, ESP32 pin ও damage হতে পারে।
T/F 7"loop_start() in Python must be called before connect() to work properly."
TTrue
FFalse
FALSE. loop_start() সাধারণত connect() এর পরে call করা হয়। connect() TCP connection establish করে, তারপর loop_start() background thread এ MQTT process করা শুরু করে।
